# 教程视频整理

来源：用户提供的 5 分 25 秒教程视频。2026-08-19 使用 `faster-whisper 1.2.1`、`small` 模型、CPU int8 在本机完成转写；视频未上传。自动语音识别可能误识别英文产品名，以下只整理与画面和仓库文件能够互相印证的流程信息。

## 核心要求

- 离线 clone 的目标是在人类使用体验和关键功能上尽可能接近真实网站。
- 以电商为例，注册、登录、浏览/搜索/筛选、选择参数、加入购物车、结账、地址和支付相关状态都属于需要覆盖的核心表面；具体功能仍应以目标站当前事实和冻结 scope 为准。
- 不要求复制源站全部数据，但前几页能探索到的数据和详情需要形成足以支撑核心流程的本地数据集。
- 仓库内已经提供完整 Prompt；新任务主要填写 `SOURCE_URL` 和人工 `HUMAN_TRACE_TEXTS`。核心轨迹可直接采用分配表原文，也可由负责人本人补充，但 Agent 不得代写正式轨迹。

## 推荐操作顺序

1. 克隆仓库并配置 Linux 环境。
2. 从任务分配表选择目标网站，将源站 URL 和核心任务原文填入启动 Prompt。
3. 在 Codex 或 Claude 的 Plan Mode 中启动任务，审阅计划并回答执行中真正需要人的问题。
4. 如果需要登录，由负责人在浏览器中亲自完成登录；不要把凭据交给 Agent。
5. Agent 持续实现并运行诊断，直到形成可人工验收的版本。
6. 参照仓库 `ACCEPTANCE.md`，把源站和本地 clone 左右分屏，亲自滚动、点击和执行相同轨迹；发现视觉或交互问题后，把具体现象反馈给 Agent 修复。
7. 确认核心功能完整后，检查对应站点的 `materials`、Harbor instance/site 等产物；可参考仓库已有示例，但不得复制其他站点的 case 或 oracle 冒充当前站点证据。

## 安全解释

视频中“完整实现注册、支付、评论、预约”等表述是对 **clone 能力和本地状态语义** 的要求，不等于授权在源站执行注册、评论、预约、订阅、下单或付款。当前 5 个任务均保持源站写操作、真实邮件、真实支付、push、PR 和公网部署未授权；需要时必须单独请求。
