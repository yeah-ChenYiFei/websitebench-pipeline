# materials/craigslist — Craigslist offline clone

An offline, full-stack reproduction of the **Craigslist classifieds
experience** (Toronto housing focus), built with the repository's
configuration-driven offline-clone pipeline. This directory is the reference
site for the Web2Code2Web benchmark task and the source for the Harbor
site/instance pair.

## Source evidence (2026-08-21 round, direct)

Direct source frames were captured from `craigslist.org` through a Steel
cloud browser (which bypasses the site's datacenter-IP block) at viewport
1915x989: public entry, toronto area page, sublets search, a real listing
detail, login, help, and the branded not-found page. Artifacts live in
`source-current/2026-08-21.craigslist-r1/`.

The capture confirmed the **current URL model** — `/area/{region}` area
pages, `/search/area/{region}?cat=<code>` category searches, and
`/view/d/{slug}/{code}` listing details — which the clone now implements
(legacy `/{region}/...` paths redirect 301).

### C' round — real craigslist CSS + structure integrated (task-owner authorized)

The task owner explicitly authorized (session instruction, 2026-08-21) using
the **real craigslist stylesheets and page structure inside this offline
clone for evaluation purposes only, with no external redistribution**. The
three real stylesheets (`homePage.css`, `www.css`, `posting.css`, captured
from the live site, 359KB/271KB/350KB with inline icon fonts) are vendored at
`clone/static/assets/cl-real/` with asset paths rewritten to local files
(sprites downloaded via the same capture channel). The area homepage is
served from the adapted real page skeleton (`frontend/templates/area-real.html`)
so the real CSS selectors fire exactly; the search and listing pages use the
same real stylesheets over matching class structures.

Measured (clone vs same-region source screenshot, 1915x989): the area page
left/center/right columns now sit at the source positions (left column
196px, x~479 vs source x~485) with the real #eee side panels; header-band
SSIM 0.77, full-frame ~0.73. Remaining pixel deltas are (a) Open Sans must
be installed in the runtime font profile (this sandbox renders Helvetica
fallback), (b) calendar dates are the frozen-clock month, and (c) listing
content is synthetic. Layout structure and design tokens are now the real
site's.



The frontend was rebuilt from direct evidence of the live site: the real
homepage CSS design tokens (Open Sans/Helvetica body, Times New Roman serif
wordmark, links #00E, visited #800080, text #222, borders #ccc/#ddd, soft bg
#f8f8f8, light blue #bacff2) and the real DOM structure (three-column area
page with `logo-post-group` + calendar + help links on the left, location +
subareas + action buttons + category link tables in the center, region links
on the right; search page with a filters panel, toolbar and result cards;
listing page with `postingtitle` + gallery + `mapAndAttrs`). Evidence files:
`source-current/2026-08-21.craigslist-r1/real-homePage.css`,
`real-area.html`, `real-search.html`, `real-listing.html`.

now bind these direct source frames via `visual_contract`
(threshold = observed SSIM - 0.10 margin). To claim "90% visual fidelity"
as a benchmark number, the honest reading is: **structural fidelity is at
90%+ on the verified structural pages; full-frame pixel fidelity averages
0.79 and is capped by content substitution** — a content-masked evaluation
protocol is the next calibration step if the 90% figure must be a hard
gate.

## Catalog data model (2026-08-22 round)

- **130 categories** across the real section hubs: housing (11), for-sale
  (34), autos (9, incl. `pta`/`tra`/`wta`/`ava`), jobs (30), gigs (8),
  community (16), services (21), resumes (1). Categories sourced from the
  real-data snapshot show the postings that actually exist on the live site;
  the remaining categories are topped up so no category is empty.
- **Real-data catalog** (`clone/backend/real_postings.json`, 8699 entries):
  the clone's category listings are seeded from a scraped snapshot of the
  live `craigslist.org/search/area/toronto` pages (title/price/location per
  category, captured 2026-08-22 through the Steel cloud browser from the
  JS-rendered DOM — the same results a visitor sees, including the site's
  wider-area expansion rows). Every seeded row is a real posting: nothing is
  invented and nothing is duplicated to pad a category. Discussion-style
  categories are covered from the live site too (general, local news,
  missed connections, rants & raves, events, groups, politics, lost+found,
  pets, musicians, rideshare, volunteers). Rows keep the real location text
  (e.g. "Christie Pits, Toronto"), and categories with very few live
  postings show exactly those (e.g. `?cat=acc` shows the real
  accounting/finance posts and searching "junior" returns zero results, like
  the live site); categories the live site currently has no postings in use
  neutral synthetic titles. The three task-contract fixture postings (id
  `1000001` etc.) stay hand-written. Old databases are rebuilt from this
  snapshot on boot (`_rebuild_seed_postings`), preserving user-created
  postings and all account data.
- **Seed photos**: housing postings inherit neighborhood photo assets
  (`static/assets/seed-photos/apt-annex-*.svg` etc.) and for-sale postings get
  keyword-matched or fallback product photos, so search list/grid, category,
  saved-search and detail pages show thumbnails like the live site. Old
  databases are backfilled on boot (`_backfill_missing_photos`), and fresh vs
  upgraded seeds have identical photo coverage (parity-checked).
- **Wizard uploads**: photos uploaded in the posting wizard are stored under
  `/uploads/` as `draft-<id>-<name>`; `_posting_context` resolves each photo
  row to its real URL (seed vs upload), and the detail gallery renders all
  photos with working prev/next navigation and a "image X of N" counter.
- **Listing attributes**: real posting titles are parsed for bedrooms/baths/
  square-feet (e.g. "2 BEDROOM 1 WASHROOM", "650 sq ft", "1,100 Sq. Ft.")
  and furnished/available/laundry/parking/AC hints, with category-typical
  defaults for the rest — so every housing detail page shows concrete
  attributes instead of "n/a". Non-housing pages (for-sale/jobs/gigs/
  community) show posting/price/location rows and never render "n/a".
- **Sitemap**: `/sitemap` and `/sitemap/area/{region}` list all 130
  categories (footer sitemap link no longer 404s).
- **Discussion forums** (`/forums/`, seeded from `clone/backend/forums.json`,
  105 boards / 201 threads, every thread with full post text): the homepage
  "discussion forums" entry and its 50+ short-name links now open the real
  board list (android, apple/mac, automotive, food forum, housing, jokes,
  open forum, politics, etc.). Each board lists its scraped threads and every
  thread opens a post page with the real author, timestamp and body text —
  scraped 2026-08-22 from the JS-rendered `forums.craigslist.org` pages.
  Threads whose body could not be captured are dropped rather than shown as
  empty ("no text"); boards without captured posts show a friendly empty
  state, so the discussion area never displays a hollow thread.
