# 反复踩到的判断错误（2026-08-29 ~ 30）

记录这些不是为了自责，而是因为**同一个模式当天重复出现了多次**，
下一轮不看这份记录就会再犯。每条都附实例与当时的代价。

## 模式一：拿两组不对齐的东西比

判断"有没有差异"时，两侧必须是同一口径。否则得到的差异全是假的，
而假差异会把注意力引向错误的方向。

| 实例 | 后果 |
|---|---|
| 拿用户未确认页面的浏览器读数，去比我这边的课程详情页 | 得出"源站不溢出、克隆溢出"，结论碰巧对但证据无效 |
| DevTools 停靠位置不同 → 视口宽度不同，两次读数不可比 | 一度宣布"读数作废"，其实结论稳定 |
| `link_diff` 第一版按**下标**配对两组长度不同的链接 | 报出 **22 万条**假差异；改成按集合比后真实值是 2,571 |
| 并发测试只发单个请求（既有 6 条结算测试全绿） | 漏掉竞态：8 个并发确认成功 3 次 |

**做法**：比之前先问"这两组的口径一样吗"。不一样就先对齐，再比。

## 模式二：把"我没找到"当成"不存在"

用一个不充分的检索方式得出否定结论，然后据此做决定。

| 实例 | 真相 | 代价 |
|---|---|---|
| "177 个静态资产从未采集" | 早已下载在用户机器上；是我的 `localize_css` 不处理同源绝对路径 | 差点让用户重复采集已有的东西 |
| "登录态首页从未采集"（grep "WELCOME BACK" 无结果） | 一直在 `recon/after-login.html`；那几个字是**图片**里的 | 登录后一直显示匿名首页 |
| "`/pimage/...` 引用是构建器截断的" | 源站自己就截断的，抓取件里一模一样 | 险些"修"出一个与源站的差异 |

**做法**：否定结论要有正面证据支持（例如"目录里确实没有这个文件"），
而不是"我搜了一下没搜到"。

## 模式三：把自己发明的标准当成任务目标

用户的要求是 A，我给自己加了标准 B，然后为达成 B 去改本来能用的东西。

| 实例 | 用户实际要的 |
|---|---|
| 为让"同子类优先"这句文档描述成真，重写替身算法并全站重建 | 「点进去有东西就可以了」——文档描述才是该改的那个 |
| 把"相似度提升"当成目标，反复调整 | 「能跑通原网站的闭环」 |

**做法**：文档与实现不符时，先问**哪一边才是用户要的**。多数情况下改文档。

## 模式四：测试通过 ≠ 测试有效

| 实例 | 问题 |
|---|---|
| `test_substitution_is_deterministic` 依赖一个我从未生成的属性 | 正则匹配不到任何东西，空转通过 |
| 三条 known-difference 的 `guarded_by` 指向**不存在的测试文件** | 三条差异长期无人守护 |
| `test_unencoded_hrefs...` 只检查 href 里没有空格，从不请求那些路由 | 3 条真实页面持续 404 期间它一直是绿的 |
| `mutation_check` 解析失败被 `except: pass` 吞掉 | 7 次注入全部"通过" |

**做法**：写完测试**注入一个破坏，确认它会红**。独立评审那句话是要点：
**「存在」不等于「验证了该条陈述」**——测试失败时，是否正好意味着该条陈述被违反？

## 模式五：只在预想的调用形态下验证

`strip_video` 的正则在**嵌套** div 上失效（534/1009 页标记失衡）；
结算不变量在**并发**下失效；持久化在**跨进程**下未验证；
`detail_allow` 与**实际构建结果**不一致（换掉了本来能用的链接）。

**做法**：问"这段逻辑在什么输入形态下会失效"，而不是"它在我写的用例下过不过"。

## 一句总结

今天修的每个重要缺陷，都不是"没想到要做"，而是**验证方式本身有盲区**。
自动化检查全绿的同时，一半页面的 DOM 是坏的、4 万条链接指错、登录后是匿名页。

## 2026-08-30：执行顺序的坑第二次出现（合并也会重铺 CSS）

已记过一次「CSS 本地化必须排在**构建**之后」。这次是同一个坑的另一面：
`merge_assets.py` 按 URL→名字从 `incoming/` 重新拷贝，会把**已经本地化过的
CSS 覆盖回原始抓取件**。补一个漏抓资产跑了一次合并，23 个 CSS 的
`@import url(//fonts.googleapis.com/...)` 就这样复活，离线闭包被破坏。

**当时没有任何检查发现它**：113 条测试全绿、三套浏览器审计 72 项全绿、
precheck 0/0。浏览器审计发现不了是因为它们只统计**失败**请求——
外部请求会**成功**，只是打到了第三方。

**正确顺序**：`build_pages.py` → `merge_assets.py` → `localize_css.py` → `gen_manifest.py`。
本地化必须排在**构建和合并两者之后**。

**已加守卫**：`tests/test_offline_closure.py`，直接钉产物里的引用本身
（CSS 的 `url()`/`@import`、页面的 `<link rel=stylesheet>`/`<script src>`），
三种破坏注入均确认会变红。
